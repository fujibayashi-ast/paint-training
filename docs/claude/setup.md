# プロジェクト初期セットアップ

`/setup` スキルがユーザーにヒアリングする際の項目をまとめたドキュメント。スキル本体の手順は [.claude/skills/setup/SKILL.md](../../.claude/skills/setup/SKILL.md) を参照。

## 使い方

1. このテンプレートをベースに新しいリポジトリを作成する
2. ユーザーが Claude に「セットアップをお願いします」と依頼する
3. Claude が `/setup` スキルを起動し、本ドキュメントのヒアリング項目に沿って 1 つずつ質問する
4. 回答に応じて `CLAUDE.md` / `README.md` / 必要な初期ドキュメント / `docs/claude/build.md`（配布物あり時）/ `.github/workflows/ci.yml`（CI 有効時）などが更新される

## ヒアリング項目

### 1. プロジェクト概要

* プロジェクト名
* 何をするアプリ / ライブラリ / ツールか（2〜3 行）
* 想定ユーザー

### 2. 技術スタック

* 言語（例: TypeScript / Python / Go）
* フレームワーク（例: React / Next.js / FastAPI）
* DB / ストレージ（例: PostgreSQL / SQLite / S3）
* パッケージマネージャ（例: yarn / pnpm / npm / uv）
* その他主要ライブラリ

### 3. アーキテクチャ

* ディレクトリ構成（主要レイヤーと責務）
* クライアント / サーバーの分離があるか
* プロセス構成（Electron のメイン / preload / renderer など）

### 4. ドメインルール

* ドメイン固有の不変条件・制約があるか
* 状態遷移や計算ルールで特筆すべきものがあるか
* 該当なしならセクションごと削除

### 5. コーディング規約

* コンポーネント / 関数 / ファイルの分割基準（例: 200 行を超えたら分割）
* 命名規則
* 共通処理の配置場所（例: `src/helpers/` に切り出す）
* 禁止事項（例: 特定ライブラリを使わない、外部通信を追加しない）

### 6. ドキュメントルール

* 更新を必須とする docs はあるか（例: シーケンス図・ER 図・テストケース）
* 記法の指定はあるか（例: Mermaid）
* docs 配置のルール

### 7. リリース・配布

* GitHub Release を使うか
* パッケージ配布（npm / PyPI / App Store など）があるか
* バージョニング方針（SemVer / CalVer など）
* 配布物がある場合、ビルドコマンドと成果物パス（`docs/claude/build.md` として保存される）

### 8. CI

* GitHub Actions で CI を有効にするか
* 実行したいチェック（lint / typecheck / test / build など）

### 9. セキュリティ・運用ポリシー

* 外部通信の可否
* 機密情報の取り扱い（環境変数 / シークレットストア）
* 監査ログや個人情報の扱い
* 業務用プロジェクトの場合、ヒアリング後に `/safe-mode` を案内する

## ヒアリング後の更新対象

LLM は回答をもとに以下を更新する:

* `CLAUDE.md` の各セクション
* `README.md` をプロジェクト用の内容に書き換える（テンプレート紹介 → プロジェクト概要・セットアップ手順）
* 必要に応じて `docs/` 配下の初期ドキュメント（architecture.md / requirements.md など）
* 配布物がある場合、`docs/claude/build.md` を作成
* CI 有効の場合、`.github/workflows/ci.yml` を技術スタックに応じて埋める。無効の場合は削除
* `.github/PULL_REQUEST_TEMPLATE.md` と `.github/ISSUE_TEMPLATE/` のプロジェクト名参照箇所

## 運用

* 項目ごとに質問し、ユーザーの回答を確認してから次に進む
* 該当しない項目は無理に埋めず、CLAUDE.md の該当セクションごと削除してよい
* 不明点は「後で記入」でスキップ可能にする
