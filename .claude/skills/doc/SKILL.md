# ドキュメント更新

## ルール

- コードの振る舞いから逆算してドキュメントを書く（推測ではなく実装を根拠にする）
- 既存ドキュメントとの整合性を保つ
- シーケンス図・ER 図は Mermaid 記法で記述する（プロジェクトの規約があればそれに従う）

## 手順

### 1. 対象を特定する

`$ARGUMENTS` で対象が渡された場合はそれを使う。渡されていない場合はユーザーに「どの機能・ファイルのドキュメントを更新するか」を確認する。

### 2. 関連コードを読む

対象機能の実装コード・型定義・関連する既存ドキュメントを Read して把握する。

### 3. 更新先を決める

CLAUDE.md / docs/ 配下の既存ドキュメントを確認し、更新すべきファイルを特定する。必要なら新規ファイルを作成する。

- アーキテクチャ変更 → `docs/architecture.md`
- 要件変更 → `docs/requirements.md`
- DB スキーマ変更 → `docs/er.md`
- 複雑な処理フロー → `docs/sequence/*.md`（シーケンス図）
- ビルド・配布手順 → `docs/claude/build.md`
- ワークフロー変更 → `docs/claude/workflow.md`

### 4. ドキュメントを作成 / 更新する

実装から読み取った内容を元に、該当ファイルを更新する。

- 既存セクションに追記する場合は、他のセクションのスタイル・粒度に合わせる
- 図が必要な場合は Mermaid で記述する
- 実装と食い違う既存記述を見つけたら指摘し、どちらを正とするかユーザーに確認する

### 5. サイトマップを更新する

ファイルを新規作成・削除した場合は `docs/README.md` の索引も合わせて更新する。既存ファイルの更新だけならこのステップはスキップしてよい。

### 6. ユーザーに提示する

変更内容をユーザーに提示し、意図通りかを確認する。

### 7. 結果を報告する

更新したファイル一覧と、見つかった実装・ドキュメントの不整合（あれば）を報告する。
